**소스 18곳의 확인 상태는 점검표 파일에 있다.** 새 소스를 볼 때마다 그 파일을 갱신할 것.

`scripts/` 에 있는 것 — `spec_lofin.py`(명세 받기) · `probe_lofin.py`(되는지 눌러 보기) ·
`build_map.py`(지도 엑셀 굽기) · `fetch_lofin.py`(실제 수집). 앞의 셋은 지도를 만드는 쪽,
마지막 하나가 데이터를 받는 쪽이다. **지도 엑셀은 손으로 고치지 말 것** — 다시 구우면 덮어쓴다.

화면을 굽는 것은 넷이다.

```
fetch_indicators.py   지표 28종을 243곳 전수로 받는다        → data/indicators/
build_model_data.py --all   자치단체별로 묶고 순위를 매긴다   → site/data/loc/<코드>.json + index.json
build_ongoing.py --all      진행 중인 사업(QWGJK)을 쪼갠다     → site/data/ongoing/<코드>.json
build_model_page.py         목록만 끼워 페이지를 굽는다        → site/index.html
```

**페이지에 박히는 것은 243곳 목록(23KB)뿐이다.** 고른 곳의 파일만 화면이 그때 받아 온다 —
243곳을 통째로 담으면 2.3MB 라 첫 화면이 무거워진다.
**`site/index.html` 은 손대지 말 것** — `model.template.html` 을 고치고 다시 구울 것.

## 기준을 섞지 말 것

**화면은 「결산 기준」과 「예산 기준」 두 판으로 나뉜다.** 섞으면 아무 말도 안 된다.

| 기준 | 무엇인가 | 최신 |
|---|---|---|
| **결산** | 이미 쓰고 확정된 실적. 다시 안 바뀐다 | 2024 |
| **실적** | 계약 실적(수의계약비율 하나) | 2024 |
| **예산[당초]** | 그 해 처음 짠 예산 | **2026** |
| **예산[최종]** | **추경까지 반영된** 예산. 추경이 끝나야 나와 한 해 늦다 | 2025 |
| 예산 | 당초/최종 구분이 없는 것들. API 가 시점을 안 밝힌다 | 2026 |

⚠️ **1차·2차 추경은 구분할 수 없다.** 지방재정365는 「최종예산」 하나만 준다.
당초와 최종의 차이가 곧 그 해 추경 전부다 — **전국 중앙값 +13.7%, 최대 +49.7%**.
당초만 보면 살림의 8분의 1을 놓친다.

⚠️ 당초는 2026 까지, 최종은 2025 까지다. **추경 증가율을 낼 때는 같은 해끼리 견줘야 한다.**

**⑤를 앞에 두지 말 것.** 수의계약비율부터 들이대면 맥락 없는 고발이 된다. 앞의 넷이
쌓아 준 무게를 업어야 한다. ⑥은 비율에서 이름으로 내려가는 마지막 칸이다.

⚠️ **비율만 보여주면 안 된다.** 비율 지표는 전부 세출결산액이 분모인데,
**금액 칸이 이미 같은 응답에 들어 있다**(`pfa_amt1`·`ane_stl_amt` 따위).
`rate` 한 칸만 뽑고 있어서 화면에 금액이 한 푼도 없었다 — 2026-09-21 에 발견했다.

## 갱신 주기

**수집은 매일(자동), 발표는 연 2회(사람).** 이 둘을 섞지 않는다.

- 발표 시점은 재정 달력에 붙인다 — **9월 결산 · 12월 예산 확정 · (선택) 6~7월 추경**
- 그래서 **연 단위 결산 계열이 1순위**다. 한 번 확정되면 안 바뀐다
- ⚠️ **일별 집행(`QWGJK`)을 2026-09-21 에 다시 올렸다.** 사용자가 「진행 중인 사업이 보였으면
  좋겠다」고 해서다. 그날 아침까지 "내렸다"고 적어 둔 것을 뒤집는다. 대신 **화면에 기준월을
  크게 박아 둔다** — 연 2회 갱신하는 사이에 숫자가 낡는 것이 이 축의 위험이다
- 다만 **계약(`WCEGCF`)·보조금(보탬e)은 매일 쌓는다.** 날짜로만 뽑혀서 안 쌓으면 소급이 안 된다.
  보여주는 건 결산 시즌에 "작년 1년치"로 묶어서
- ⚠️ **한 번에 다 받으려 하지 말 것.** 일일 트래픽 제한이 있을 수 있는데 실측이 안 됐다.
  기관에 묻는 대신 **조금씩 받아 채운다**(2026-09-21 결정). 그래서 수집기는 전부
  **이어받기**(이미 받은 것은 건너뛴다)와 **`--limit`**(이번엔 여기까지)를 갖춘다

## 누가 무엇을 하나

저장소에 쓰는 사람은 **Claude 하나다.** 점검표가 엑셀이라 둘이 고치면 병합이 안 된다.
GPT 는 **계정·로그인이 있어야 보이는 곳**을 맡아 확인하고 결과를 글로 넘긴다.

⛔ **지방의회 자료(CLIK)는 사용자가 GPT 와 정한다**(2026-09-21). Claude 는 손대지 않는다.

⚠️ **인증키 값은 저장소에 적지 않는다.** 공개 저장소다. 점검표에도 「있음/없음」만 적고,
값은 `.env` 와 깃허브 Secrets 로만 간다.

점검표의 **「확인자」 칸**에 누가 본 것인지 적는다 — 직접 호출해 본 것과 화면만 본 것은
신뢰도가 다르다.

## 키

`.env` 에 넣는다(`.env.example` 참고). **깃에 올리지 않는다.**
지방재정365는 키 하나로 146종이 전부 열리고, data.go.kr 은 API 마다 활용신청을 따로 해야 한다.

## 정해 주셔야 할 것

Claude 혼자 정하면 안 되는 것들만. 정해진 것은 「기록」의 2026-09-21 칸으로 옮긴다.

1. **계약 원본을 저장소에 둘까, 밖에 둘까?** 3년치면 **165MB** 다(하루 0.165MB).
   칸을 몇 개 빼도 17%밖에 안 준다. — *내 생각: 저장소 안. 여러 PC 에서 일하고, 매일 도는
   액션도 저장소에 커밋하는 식으로만 쌓을 수 있고, 무엇보다 **기관이 자료를 내려도 우리에게
   남는다.** 감시하는 쪽에는 그게 값어치다.*
2. **깃허브 Secrets 에 인증키를 내가 넣을까, 직접 넣으실까?**
   ⚠️ 보안 위험은 낮다 — 암호화돼 들어가고 로그에 찍히면 가려지고 포크에는 안 넘어간다.
   키가 새도 남이 우리 할당량을 쓰는 정도고 언제든 다시 받을 수 있다.
   다만 **키 값을 이 PC 밖으로 내보내는 일**이라 내 손으로 하기 전에 묻는다.
3. **교육·공론장에 쓸 종이가 필요한가?**(6번을 다시 적는다) 이런 것들을 말한 것이다 —
   참가자가 자기 동네 숫자를 적어 넣고 옆 사람과 견주는 **한 장짜리 워크시트**,
   진행자가 화면을 띄워 놓고 넘길 **슬라이드**, 인터넷 없이 볼 **인쇄물 한 장**.
   지금 정할 필요는 없고 **11월 초 전에** 정하면 된다.
4. **순위를 광역/기초로만 가르는 게 맞나?** 지금은 수원시(120만)와 옹진군(2만)이 같은
   226곳 안에서 견줘진다. 인구나 재정 규모로 묶는 쪽이 나을 수도 있다.
5. **보조금 받은 쪽이 개인이면?** 보탬e 를 받아 보면 섞여 있는지 알 수 있다. 받고 나서 다시 여쭙는다.
6. **집행률 20% 밑을 붉게 칠하는 것**, 이대로 둘까?

## 기록

### 2026-09-21 — 정해진 것들 (사용자 결정)

물어본 17가지 중 열셋이 정해졌다.

**받는 것**
- **계약은 3년치를 소급해 받는다**(2024·2025·2026). "그래야 지금이 어떤지 보인다."
  `backfill_contracts.py` 가 하루씩 채운다 — **이어받기가 되니 끊겨도 다시 부르면 된다.**
- **보탬e 지방보조금은 전수로 받는다.**
- **국고보조금도 붙여 본다** — 다만 "쓸 만할지는 모르겠다"는 단서가 붙었다.
- **교육청(지방교육재정알리미)은 별도 꼭지로 하긴 한다.** 지금은 아니다.
- ⛔ **지방의회(CLIK)는 Claude 가 손대지 않는다.** 어떻게 할지 사용자가 GPT 와 정한다.

**드러내는 것**
- **계약 업체는 이름까지만.** 대표자·사업자번호는 뺀다. "필요할 때가 있겠지만 일단 뺀 형태로."

**사이트**
- **서브도메인으로 간다. 다만 아직 가안이다 — ⛔ 도메인 연결은 사용자가 말할 때까지 하지 말 것.**
- **첫 화면은 사례로 연다** — 들여다본 사례 하나를 앞에 놓고, 그 아래로 내 동네 찾기.
- **바뀐 구역(광주+전남·인천)은 따로 두고 안내만 한다.** 2026 결산이 나오면 자연히 풀린다.
- **시계열은 5년치만. 그리고 결산용과 예산용을 따로 간다**(2026-09-21 추가 결정).
  결산 시계열 **2020~2024**, 예산 시계열 **2022~2026** — 한 그림에 섞지 않는다.
- **자동 수집은 켠다.** "호출이 정해져 있다면 켜놓고 데이터 모으는 게 필요하다."
- ⏳ **11월 초에는 얼추 뭔가 정해져 있어야 한다**(변화의 시나리오 일정). 이게 사실상의 기한이다.
- **여수섬박람회는 실험이었다** — "사업을 쪼개서 볼 수 있는지 확인한 것뿐"이고
  **구체적 기획은 아직 없다.** 사례 꼭지를 지레 짜 놓지 말 것.

**주기·한도**
- ⚠️ **일일 트래픽 제한은 기관에 묻지 않는다.** 사용자 판단 —
  **"할 수 있을 만큼 조금씩 받아서 채우면 된다."** 그래서 수집기는 전부
  **이어받기(이미 받은 것은 건너뛰기) + `--limit`** 를 갖춘다. 한 번에 다 받으려 하지 말 것.
- **열린재정 `ERROR-310` 문의는 후순위.**

**첫 독자 — 이게 제일 크다**
- 이 사이트는 **아름다운재단 「변화의 시나리오」 사업과 엮인다.**
  띄우고 끝이 아니라 **그것으로 교육을 하고 공론장을 연다.**
  → 혼자 보는 대시보드가 아니라 **여럿이 놓고 이야기할 판**으로 짠다.
  사례 하나를 끝까지 따라가는 꼭지가 그래서 쓸모가 크다.

**아직 못 정한 것** — 보조금 수령자가 개인일 때 · 집행률 붉은 칠 기준
(위 「정해 주셔야 할 것」에 남겨 뒀다).

### 2026-09-18 — 데이터 확보
- 지방재정365 146종, 열린재정 198종의 **서비스코드를 전부 확보**했다. 둘 다 SPA 라 목록 API 를 직접 찾아 긁었다.
- 열린재정은 접두어가 `OPFI`/`TB_OPFI`/`OPFB` 셋이고 `VW_` 가 붙는 게 25개 섞여 있다. WAF 가 curl 을 막아 **브라우저 User-Agent 가 필요**하고, 상세는 `www` 가 아니라 **`opms` 호스트**로 가야 POST 가 통한다.
- 열린재정 107종이 `ERROR-310` 을 뱉는다. **주요·통합재정통계는 100% 되는데 상세재정통계·월간재정동향은 통째로 안 된다.** 키 권한 범위인지 미공개인지 모른다 — 문의하면 풀릴 사안.
- 열린재정은 전부 중앙정부 총량이라 **자치단체로 안 쪼개진다.** 우리 사이트엔 비교 맥락용이다.
- 나라장터 계약정보에 **업체명·대표자·사업자번호·수의계약 여부**가 나온다. 지방재정365에 없는 "누가 받았나"가 여기 있다.
