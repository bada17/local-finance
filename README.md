화면을 굽는 것은 셋이다 — `fetch_indicators.py`(지표) → `build_model_data.py`(자치단체별로 묶기) →
`build_model_page.py`(`site/index.html` 굽기). 여기에 `build_ongoing.py`(진행 중인 사업)가 붙는데,
이것만 `site/data/ongoing/<코드>.json` 으로 따로 나간다 — 한 곳에 2천 건이 넘어 페이지에 못 담는다.
**`site/index.html` 은 손대지 말 것** — `model.template.html` 을 고치고 다시 구울 것.

## 기준을 섞지 말 것

**화면은 「결산 기준」과 「예산 기준」 두 판으로 나뉜다.** 섞으면 아무 말도 안 된다.

| 기준 | 무엇인가 | 최신 |
|---|---|---|
| **결산** | 이미 쓰고 확정된 실적. 다시 안 바뀐다 | 2024 |
| **실적** | 계약 실적(수의계약비율 하나) | 2024 |
| **예산[당초]** | 그 해 처음 짠 예산 | **2026** |
| **예산[최종]** | **추경까지 반영된** 예산. 추경이 끝나야 나와 한 해 늦다 | 2025 |
| 예산 | 당초/최종 구분이 없는 것들. API 가 시점을 안 밝힌다 | 2026 |

⚠️ **1차·2차 추경은 구분할 수 없다.** 지방재정365는 「최종예산」 하나만 준다.
당초와 최종의 차이가 곧 그 해 추경 전부다 — **전국 중앙값 +13.7%, 최대 +49.7%**.
당초만 보면 살림의 8분의 1을 놓친다.

⚠️ 당초는 2026 까지, 최종은 2025 까지다. **추경 증가율을 낼 때는 같은 해끼리 견줘야 한다.**

**⑤를 앞에 두지 말 것.** 수의계약비율부터 들이대면 맥락 없는 고발이 된다. 앞의 넷이
쌓아 준 무게를 업어야 한다. ⑥은 비율에서 이름으로 내려가는 마지막 칸이다.

⚠️ **비율만 보여주면 안 된다.** 비율 지표는 전부 세출결산액이 분모인데,
**금액 칸이 이미 같은 응답에 들어 있다**(`pfa_amt1`·`ane_stl_amt` 따위).
`rate` 한 칸만 뽑고 있어서 화면에 금액이 한 푼도 없었다 — 2026-09-21 에 발견했다.

## 갱신 주기

**수집은 매일(자동), 발표는 연 2회(사람).** 이 둘을 섞지 않는다.

- 발표 시점은 재정 달력에 붙인다 — **9월 결산 · 12월 예산 확정 · (선택) 6~7월 추경**
- 그래서 **연 단위 결산 계열이 1순위**다. 한 번 확정되면 안 바뀐다
- ⚠️ **일별 집행(`QWGJK`)을 2026-09-21 에 다시 올렸다.** 사용자가 「진행 중인 사업이 보였으면
  좋겠다」고 해서다. 그날 아침까지 "내렸다"고 적어 둔 것을 뒤집는다. 대신 **화면에 기준월을
  크게 박아 둔다** — 연 2회 갱신하는 사이에 숫자가 낡는 것이 이 축의 위험이다
- 다만 **계약(`WCEGCF`)·보조금(보탬e)은 매일 쌓는다.** 날짜로만 뽑혀서 안 쌓으면 소급이 안 된다.
  보여주는 건 결산 시즌에 "작년 1년치"로 묶어서

## 누가 무엇을 하나

저장소에 쓰는 사람은 **Claude 하나다.** 점검표가 엑셀이라 둘이 고치면 병합이 안 된다.
GPT 는 **계정·로그인이 있어야 보이는 곳**을 맡아 확인하고 결과를 글로 넘긴다.

⚠️ **인증키 값은 저장소에 적지 않는다.** 공개 저장소다. 점검표에도 「있음/없음」만 적고,
값은 `.env` 와 깃허브 Secrets 로만 간다.

점검표의 **「확인자」 칸**에 누가 본 것인지 적는다 — 직접 호출해 본 것과 화면만 본 것은
신뢰도가 다르다.

## 키

`.env` 에 넣는다(`.env.example` 참고). **깃에 올리지 않는다.**
지방재정365는 키 하나로 146종이 전부 열리고, data.go.kr 은 API 마다 활용신청을 따로 해야 한다.

## 기록

### 2026-09-18 — 데이터 확보
- 지방재정365 146종, 열린재정 198종의 **서비스코드를 전부 확보**했다. 둘 다 SPA 라 목록 API 를 직접 찾아 긁었다.
- 열린재정은 접두어가 `OPFI`/`TB_OPFI`/`OPFB` 셋이고 `VW_` 가 붙는 게 25개 섞여 있다. WAF 가 curl 을 막아 **브라우저 User-Agent 가 필요**하고, 상세는 `www` 가 아니라 **`opms` 호스트**로 가야 POST 가 통한다.
- 열린재정 107종이 `ERROR-310` 을 뱉는다. **주요·통합재정통계는 100% 되는데 상세재정통계·월간재정동향은 통째로 안 된다.** 키 권한 범위인지 미공개인지 모른다 — 문의하면 풀릴 사안.
- 열린재정은 전부 중앙정부 총량이라 **자치단체로 안 쪼개진다.** 우리 사이트엔 비교 맥락용이다.
- 나라장터 계약정보에 **업체명·대표자·사업자번호·수의계약 여부**가 나온다. 지방재정365에 없는 "누가 받았나"가 여기 있다.

### 2026-09-21 — 지방재정365 데이터 지도
**146종이 전부 열린다.** 하나씩 눌러 보고 공식 명세까지 받아 지도로 만들었다.

- 명세는 화면 조각으로만 온다. `…/dtstSvi/retvDtstDtsApi.do` 에 **폼 인코딩**으로 `pdtaId`
  하나만 POST 하면 요청인자 표와 출력값 표가 든 HTML 이 통째로 온다(JSON POST 는 안 먹는다).
  **146/146 받았다.** 출력 항목에 한글 이름이 붙어 있어, 이게 없으면 필드 뜻을 알 수 없다.
- 필수인자는 `fyr` 하나뿐인 것이 101종, 아예 없는 것이 40종이다. 나머지 다섯이 날짜·코드를 받는다.
- **일별 축은 넷** — `QWGJK` 세부사업별 세출 · `HCFDA` 분야별 세출 · `SIHHC` 세입현황 ·
  `WCEGCF` 계약현황. 필수인자 이름이 제각각이라(`exe_ymd`·`txrv_ymd`·`smz_ctrt_ymd`)
  명세를 보기 전에는 못 맞힌다. 이 넷 때문에 처음엔 "안 되는 서비스"로 잘못 적었었다.
- ⚠️ **`WCEGCF` 계약현황에 업체명·계약방법·계약금액·하도급유무가 243곳 전수로 있다.**
  「누가 받았나」는 나라장터에만 있는 줄 알았는데 지방재정365 안에 있었다. 점검표를 고쳤다.
- **인증키가 없으면 한 쪽에 5행 고정이다**(틀린 키는 `ERROR-290`). 243행짜리 연 단위 자료는
  키 없이도 받을 만하지만(49번), QWGJK 전국 46만 행은 9만 번이 되어 키가 있어야 한다.
  이 PC 에 `.env` 가 없다 — **키부터 넣어야 전수 수집이 시작된다.**

### 열린재정 — 후순위로 내림
2026-09-18 에 다음 일감으로 정했다가, 2026-09-21 에 뒤로 미뤘다. 중앙정부 총량이라
자치단체로 안 쪼개지는 것이 이유다. 그 전에 풀어 둔 것과 남은 것은 이렇다.

풀린 것: 명세 엔드포인트 `opms…/op/ko/sd/dtsStatsAcol/selectAcolViewList.do` 에
JSON `{"odtId":…, "rlsSvTyCd":"A", "odtSvSeq":"2", "odtNm":<possDtaNm>, "paramVO":{"odtNm":<possDtaNm>}}`
→ 요청인자·출력필드·일일제한. **161/198 받아서 엑셀에 넣었다.** 일일제한은 서비스당 1,000회.

- **`ERROR-310` 107종은 키 문제가 아니다**(2026-09-21 확인). 키를 아예 빼고 불러 보면
  되는 서비스는 `ERROR-300`(필수값 누락), 안 되는 서비스는 `ERROR-310` 이 온다.
  **서비스 이름 검사가 키 검사보다 먼저**이므로, 권한이 막힌 게 아니라 그 이름으로 등록된
  API 가 없는 것이다. 이름 규칙(`VW_`·`TB_` 접두어)이 목록과 다르거나, 문의할 사안이다.
- 명세 못 받은 37종 중 35종이 그 107종과 겹친다. **겹치지 않는 건 `OPFI165`·`TB_OPFI193` 둘뿐**이라,
  「명세 37종 재시도」는 실제로는 2종짜리 일감이다.

### 2026-09-21 — GPT 가 계정 벽 뒤를 보고 왔다
맡겨 둔 3곳이 다 돌아왔다. 나라장터 계약과정통합공개까지 넷을 점검표에 옮겼다.

- **지방교육재정알리미가 「완료」로 올라갔다.** 실호출 성공. 예산공시 295종 + 결산공시 325종,
  17개 시·도교육청. 2024년 집행내역 2,220건에 **보조사업명·보조사업자·집행액·최종정산액**이
  나온다 — 받는 쪽 이름이 실제로 나오는 몇 안 되는 소스다. 다만 학교운영비·재정결함지원·
  사립유치원지원은 교육청별 집계라 **개별 학교명이 없다.**
  ⚠️ **업무추진비 비율이 1% 미만에서 0 으로 잘린다** — 비율 말고 원금액으로 다시 계산할 것.
- **CLIK 은 공개 샘플키로 이미 열린다.** 회의록·의안·의원·지방정책정보 4종. 명세상 범위가
  회의록 광역 17 + **기초 175**, 의안·의원 광역 17 + 기초 125 다. 회의록 상세에 **발언 전문**과
  원본 파일 URL 이 붙어 있고, 예산·결산·보조금·수의계약·업무추진비·행정사무감사 **본문 검색이
  된다.** 2026-09-18 자료까지 들어오니 살아 있다. 사용자 키는 승인 대기.
- **국고보조금은 「기획예산처_국고보조금 정보」(15097584)** 였다. 보조사업자정보공시·중요재산
  정보공시·보조사업현황 세 갈래고, 보조사업현황에 **국고보조금·지자체부담금·자부담금**이 같이
  나온다 — 보탬e(지방보조금)와 대칭으로 볼 수 있다. 본체 호출은 아직 안 해 봤다.
- 나라장터 계약과정통합공개는 물품·용역·공사·외자 **4개 경로**까지만 확인. 실호출은 남았다.

⚠️ **셋 다 아직 「부분」이거나 검사가 남았다.** 명세를 읽은 것과 데이터를 받아 본 것은 다르다 —

### 2026-09-21 — 진행 중인 사업 · 여수세계섬박람회로 시험해 봄
사용자가 「진행 중인 사업에 대한 뭔가가 있으면 좋겠다」고 해서 판을 하나 더 붙였다.
